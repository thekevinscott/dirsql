**Fixed** An `onFile` value outside the documented value types (a plain object, `Array`, `Date`, `Map`, a function, a symbol, a typed array other than `Uint8Array`, ...) now fails `ready` and every query with an error naming the column and type, instead of being silently stored as its `String()` form (`"[object Object]"`). A symbol or a null-prototype object no longer hangs the build.
