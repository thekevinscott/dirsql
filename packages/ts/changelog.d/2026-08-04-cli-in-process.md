**Changed** — the `dirsql` CLI now runs **in-process** through the napi addon instead of spawning a bundled binary. `@dirsql/lib-<platform>` is built with the core's `cli` feature and exports `runCli`, and the launcher calls it via [bin-shim](https://www.npmjs.com/package/bin-shim)'s in-process strategy. Argument handling is unchanged: every argv still goes straight to the core, which owns subcommand dispatch, and the launcher still resolves package-name extensions from a TOML config into `--extension` flags before handing over. Exit codes are unchanged — verified across `--version`, `--help`, a query, a SQL error (1), an unknown flag (2) and `dirsql server` + Ctrl-C (graceful shutdown, 0).

**Removed** — **BREAKING (packaging)**: the `@dirsql/cli-<platform>` package family is no longer published, and the main `dirsql` package no longer lists it in `optionalDependencies`. It shipped a standalone `dirsql` binary that duplicated the core already present in the addon. The per-platform native payload drops from 10,139,000 B (4,564,768 B addon + 5,574,232 B binary) to 5,799,904 B — **−42.8%**, one artifact instead of two. Nothing user-facing changes: `npx dirsql`, a global install, and the `dirsql` bin all work as before. Anyone depending on `@dirsql/cli-<platform>` **directly** — not via `dirsql` — must switch to `@dirsql/lib-<platform>` and call its `runCli` export. See [MIGRATIONS.md](../../MIGRATIONS.md). #739.
