**Fixed** A query applies the file watcher's queued events instead of walking the tables' globs, and checks foreign keys only once that queue is empty. A writer creating a parent file and then its child no longer fails concurrent queries with a foreign-key violation. On Linux a query first drains every event the kernel has queued, so a write that returned before the query is read; on macOS and Windows a query applies what the watcher has delivered, so a query issued the moment a write returns may still see the old rows. A file whose `on_file` fails after the build fails every query with that error until the file is fixed or removed.
