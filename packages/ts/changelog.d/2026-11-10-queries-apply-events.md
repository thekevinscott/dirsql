**Fixed** A query reads the index as it stands and never waits on the file watcher, so a writer that never pauses can no longer hold a query indefinitely. The watcher's events are applied in the background as they arrive, so a write reaches the index shortly after it returns rather than being read by the next query. A writer creating a parent file and then its child no longer fails concurrent queries with a foreign-key violation. A file whose `on_file` fails after the build fails every query with that error until the file is fixed or removed. `watch()` and `pollEvents()` report the changes applied after they attach. `onFile` runs on the JS main thread, so a change reaches the index when that thread is next free.
