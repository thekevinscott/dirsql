**Added**

- **Bare `dirsql` opens a REPL over the current directory.** With no subcommand and no SQL, dirsql reads statements until EOF instead of printing a usage error: `dirsql> ` prompts and a sample-query banner when stdin is a terminal, one statement per line and no interactive furniture when it is a pipe (`dirsql < script.sql > out.json`). Statements go through the same `execute_query` pipeline `dirsql query` and `POST /query` use, so results are identical to the one-shot form. A failing statement prints its diagnostic to stderr and the session **continues** — unlike `dirsql query`, which exits 1 — and a clean EOF exits 0 regardless of per-statement failures, matching interactive `sqlite3`. Leave with `exit`, `quit`, or Ctrl-D; there are no dot-commands. The index is built once before the loop, so statements share one scan and the live watcher keeps it fresh between them. Every config flag bare `dirsql` already accepted (`-c`, `--persist`, `--no-ignore`, `--on-file`) applies unchanged, and an unusable config is reported once up front rather than on every statement.
