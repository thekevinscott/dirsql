**Fixed**

- **Editing the `ddl` of a `--persist` cache holding an extension-provided virtual table no longer wedges it.** The sweep that precedes a rebuild ran on the cache connection at the moment it was opened, before anything loaded the configured `[[dirsql.extension]]` entries — so `DROP TABLE` on a virtual table whose module came from an extension answered `SQLite error: no such module: vec0`, and every subsequent run repeated the failure until `.dirsql` was deleted by hand. The sweep now runs once the connection carries the same extensions and `[[dirsql.function]]` registrations the batch that created those tables had, so it can drop whatever that batch was able to create. FTS5 masked this: its module is compiled into SQLite and registered on every connection, loadable ones are not. (#1008)
