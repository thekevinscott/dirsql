**Added**

- **A query reports the worker round trips it is paying for.** A `[[dirsql.function]]` costs one worker round trip per row, so a query calling one over a whole corpus — `dirsql-plugin-embeddings` runs `embed(content)` that way — can run for minutes inside a single `query()` with nothing on the terminal. Core now counts the round trips and draws them with the same reporter the startup scan uses (`dirsql: running 9204 worker calls`, erased at the end of the query and replaced by `dirsql: ran 41231 worker calls in 2m41s`), under the same `DIRSQL_PROGRESS` gate: terminal-only and slow-work-only by default, silent on a pipe. A query that calls no worker prints nothing at any setting. The count is drawn **and erased by dirsql itself** rather than by the worker, which is what keeps the result off the progress line: a worker's own bar cannot be cleaned up, since the worker is SIGKILLed and is torn down only after the result has been printed. (#1001, #957)
