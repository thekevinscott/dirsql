**Changed**

- **A `DirSQL` / `AsyncDirSQL` built with no config and no programmatic tables now serves the baked-in default `files` table**, instead of an empty index — parity with the CLI's no-`-c` default (#603). `DirSQLBuilder::resolve` injects `DEFAULT_CONFIG_TOML`'s `files` table when both the config-path list and the table list are empty, so `db.query("SELECT * FROM files")` works out of the box. Explicit `.config(path)` / `from_config_path(path)` are unchanged. **Removed:** the root-joining `DirSQL::from_config(root)` / `AsyncDirSQL::from_config(root)` shortcuts (they auto-joined `<root>/.dirsql.toml`); use the explicit `DirSQL::from_config_path(root.join(".dirsql.toml"))` or `.builder().root(r).config(r.join(".dirsql.toml")).build()`. `DEFAULT_CONFIG_TOML` is now exported at the crate root (`dirsql::DEFAULT_CONFIG_TOML`); `dirsql::cli::DEFAULT_CONFIG_TOML` remains as a re-export.
