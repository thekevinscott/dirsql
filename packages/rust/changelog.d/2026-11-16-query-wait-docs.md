**Changed** Documentation only: `DirSQL::query`'s docs and the `dirsql context` troubleshooting guide now say how long a query waits. A query that arrives while a batch of file changes is being applied waits for that batch and is answered as soon as it ends. A batch is every change that was waiting when applying started and is never split, so under a writer that never pauses a query waits as long as one batch takes. This corrects the earlier statement that a query never waits on the watcher.
