**Changed** A statement that reads the same path table more than once -- three CTEs over `'./'`, a self-join, a `UNION` of selections -- walks the tree once and serves every reference from that one scan; the next statement scans afresh, so reads stay live. The scan itself is cheaper too: rows are built as compact structs rather than per-row maps, the files are stat'ed across every core, and the walker is the crate's own sorted recursive `read_dir` (the `walkdir` dependency is gone), so a path-table query over hundreds of thousands of files now runs at the speed of the equivalent `find` pipeline. `vtab::load_module` and `parsed_vtab::load_module` take the `StatementScope` the tables cache under; see the migration note.
