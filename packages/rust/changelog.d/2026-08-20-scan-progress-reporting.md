**Added**

- **The startup scan reports its progress on stderr.** A cold scan over a large corpus was silent: the walk visits every file, then each matched file costs an `on-file` round trip plus whatever the table's `ddl` fires on insert, and on a big tree that is minutes with nothing on the terminal — no way to tell a slow scan from a wedged one. Both phases now draw a counter that is rewritten in place (`dirsql: indexing 9204/41231 files (22%)`), erased when the phase ends and replaced by one summary of what it cost (`dirsql: indexed 41231 files in 3m12s`). It is **terminal-only and slow-work-only** by default: a phase finishing in under half a second prints nothing, and a run whose stderr is a pipe or a file prints nothing at any duration, so `| jq` pipelines, `2>` redirects and CI logs are byte-for-byte unchanged. `DIRSQL_PROGRESS=always` reports regardless of terminal and from the first update; `DIRSQL_PROGRESS=never` guarantees silence. The reporter lives in the core (`progress`), so it governs an index built from any SDK, not just the CLI, and it adds no dependency — the line is a `\r`-rewritten counter rather than a drawn bar, which needs the terminal width and therefore a crate.
