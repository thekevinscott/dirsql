**Changed**

- **A table's name is now declared, not derived from `ddl`.** `[[table]]` gains a required `name` key, and `Table::new` / `Table::try_new` / `Table::strict` take it as their first argument. dirsql no longer tokenizes the `CREATE TABLE` head of `ddl` to work the name out — `db::parse_table_name` is gone, along with the bespoke SQL-as-text parsing it needed for quoted, schema-qualified and `IF NOT EXISTS` forms. Whether the `ddl` actually creates a table by that name is settled after it runs, against SQLite's own catalog (`pragma_table_list`): no row means a load-time error carrying the config entry's name, raised before any file is ingested. `Db::create_table` now takes `(name, ddl)`; `validate_identifier` stays as the injection guard, since `name` is spliced into `format!()`-built INSERT/DELETE SQL. Duplicate-table detection across composed configs compares `name` keys. (#962)
