**Fixed** A `./` path-table that names a directory before its first wildcard -- `'./small/*.md'`, `'./docs'`, `'./src/**/*.rs'` -- now starts its walk at that directory instead of at the index root, so it costs what `find ./small` costs rather than what `find .` costs, however large the siblings. `path` is reported exactly as before. Two consequences follow from where the walk starts: a `.dirsql/` directly under the named directory is now the reserved one (`'./.dirsql'` scans it outright, `'./x/.dirsql'` is pruned), and a symlinked directory named outright is now entered, both as absolute tables already behave. A parser (`--on-file`) over any path-table now runs in the index root with `{root}` naming it, which absolute tables previously got wrong. The scanner's `scan_glob` drops its `ignore_base` argument, `path_table::ignore_base` is gone, and the `dirsql_parsed` module takes the index root as an argument; see the migration note.
