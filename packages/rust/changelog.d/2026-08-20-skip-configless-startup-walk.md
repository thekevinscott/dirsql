**Fixed**

- **Startup no longer walks the directory tree when no tables are declared.** Configless mode (`dirsql "SELECT * FROM './*'"`) defines zero named tables — filesystem access goes through path-tables, which mint their own per-statement scan — yet `prepare_resolved` ran the full recursive walk unconditionally. With no table globs to match against, that walk returns nothing by construction, so it was pure waste: ~78–85% of the runtime of a query that reads no files (~25 ms over 20k flat files, ~40 ms over 20k nested), scaling to seconds on a large non-repo directory or a network filesystem. The walk is now skipped when the resolved build declares no tables. Nothing else on the startup path changes — with `persist` on, the cache is still opened and reconciled against the (empty) scan, and path-table queries never consulted the startup scan to begin with. (#986)
