**Added** `[[dirsql.function]]` config entries: worker-backed SQL scalar functions. A config fragment (typically plugin-shipped) declares `name`, `args` (accepted arities, registered once per arity), `command`, optional `deterministic`, and an optional per-call `timeout` overriding `[dirsql].hook-timeout`. Registration is inert; the worker process is spawned lazily on the function's first call, kept alive for the rest of the invocation (never one process per row), speaks newline-delimited JSON over stdin/stdout (`{"call": [...]}` / `{"ok": ...}` or `{"err": "message"}`, BLOBs as `{"$bytes": "<base64>"}`, arrays bound as TEXT), passes its stderr through, and is torn down when the index is dropped. Duplicate function names across config sources are a merge error; undeclared functions keep SQLite's normal "no such function" error.
