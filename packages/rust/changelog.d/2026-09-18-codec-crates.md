**Changed**

- **The function worker's base64 codec and the CLI's hex codec are now the `base64` and `hex` crates.** The hand-rolled `base64_encode` / `base64_decode` in `functions.rs` and `hex_encode` in `cli/serialize.rs` are gone (~65 lines), along with the `clippy::cast_possible_truncation` opt-out the decoder's shifts needed. The wire format is unchanged: `{"$bytes": "<base64>"}` still uses the standard alphabet with required padding and no line wrapping, and BLOB cells still render as lowercase two-chars-per-byte hex with no separator — `base64::engine::general_purpose::STANDARD` is that configuration exactly. The decoder stays strict: a length that is not a multiple of four, a byte outside the alphabet, and padding anywhere but the close of the final chunk all still fail the query with `"$bytes" is not valid base64`. It is also strict on one input the hand-rolled decoder let through — a final character carrying non-canonical trailing bits (`"AQJ="`), which no conforming encoder emits. Costs `base64` as a dependency of the published crate (zero-dependency, `no_std`-capable, and already in the lockfile transitively, so one crate rather than a subtree); `hex` is likewise zero-dependency and sits behind the `cli` feature, so a library consumer never pulls it. (#1130)
