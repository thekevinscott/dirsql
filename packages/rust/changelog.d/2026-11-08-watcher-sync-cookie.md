**Changed** On Linux, `watcher::Watcher::try_recv_all` is a barrier: it returns every event the kernel queued before the call, including those notify had not yet handed over, by touching a sync cookie in a directory of the watcher's own under the OS temp dir. It now returns `Result<Vec<FileEvent>, notify::Error>`; a cookie that does not arrive within 10s is an error naming any error notify reported. The new `Watcher::flush` is the same call; the new `Watcher::queued` is the old non-blocking drain, and `DirSQL`'s live event loop keeps using it, so delivery latency is unchanged. The watcher's channels hold at most 16384 undrained events each; a backlog past that ends in `FileEvent::Rescan`, as an inotify queue overflow does.
