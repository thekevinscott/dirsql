**Fixed**

- **`--persist` now caches a parsed path-table's rows, so a second run over an unchanged tree re-runs the `on-file` parser for no file.** Previously the persistent cache only covered declared `[[table]]` entries: a path-table (`SELECT ... FROM './**/*.json' --on-file '<command>'`) re-scanned, re-read and re-parsed every file on every run, which made `--persist` pure overhead on the surface a configless `dirsql --persist` actually queries — measured 2.7s cold and 2.7s warm over a 2,000-file tree, versus 2.7s → 0.04s now. Each file's parser output is stored in the cache against its stat tuple (`_dirsql_parsed_rows`, reconciled by the same racy-stat rule declared tables use), keyed by the tree, glob, parser command and `dirsql` version together, so changed files re-parse and a changed command or glob starts fresh. A *stat* path-table is unaffected: its columns are the scan's own metadata and `content` stays a live read. (#825)
- **A run that changes nothing no longer rewrites the cache file.** The `_dirsql_meta` block was rewritten on every startup, so `cache.db` changed even when the tree had not; it is now written only when the meta actually differs, leaving an unchanged warm start byte-for-byte identical. (#825)
