**Changed** A statement that names a path table's `content` column -- in its projection, its `WHERE`, or across a join -- has the file bodies of the rows it selects read ahead, eight files at a time, before SQLite steps the first row, instead of one file at a time as each row is emitted. Each read is also one stat cheaper: the buffer is sized from the size the scan already recorded. A statement that does not name `content` still reads no file, `SELECT *` still excludes it, and an unreadable or non-UTF-8 file is still a `NULL` cell. In a join, the planner now scans the table whose `content` is named and probes the other, so the read-ahead covers the whole column rather than one probe at a time.
