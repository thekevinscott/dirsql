**Changed** — A duplicate table name now fails registration with a message naming the table **and both definition sites** (`Table 'notes' is defined by both a programmatic table and config /proj/dirsql.toml`); when both sides share an origin it reads `defined twice by <source>`. Previously the error was `duplicate table name: notes`, which named the table but neither definition. The public `DirSqlError::DuplicateTable` changes from a tuple variant to a struct variant `{ name, first, second }` carrying the new `TableSource` enum (`Programmatic` / `Config(PathBuf)` / `Default`). See `MIGRATIONS.md`.
