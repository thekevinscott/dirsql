### `ddl` becomes a multi-statement SQL batch, validated against the catalog (#956)

#### Summary

A `[[table]]`'s `ddl` had to be exactly one statement, and dirsql string-sniffed
it for `CREATE VIRTUAL TABLE` and `WITHOUT ROWID`. It is now a whole SQL batch,
run through `execute_batch` inside one transaction, and what it produced is
settled afterwards against SQLite's catalog (`pragma_table_list`) rather than by
reading the DDL text. `Db::create_table` keeps its `(name, ddl)` signature;
`db::is_virtual_table_ddl`, `db::is_without_rowid_ddl` and `DbError::DdlParse`
are deleted. `DirSqlError` gains `TableIsVirtual` and `TableDdl`, and
`TableNotCreated` gains a `created` field carrying the before/after catalog diff.

#### Required changes

| Before | After | Fix |
| ------ | ----- | --- |
| `Err(DirSqlError::TableNotCreated { name })` as an exhaustive pattern | Does not compile — the variant gained `created: Vec<String>` | Match `TableNotCreated { name, .. }`, or bind `created` to read what the batch did create. |
| `Err(DirSqlError::Core(_))` for a `ddl` SQLite rejects | No longer produced for that case | Match `DirSqlError::TableDdl { name, source }`; `source` is the same `DbError` as before, and `Display` prefixes it with `table '<name>': `. |
| `DbError::DdlParse` constructed or matched | Does not compile | Nothing produces it any more. A rejected batch is `DbError::Sqlite`, reached through `DirSqlError::TableDdl`. |
| `ddl = "CREATE VIRTUAL TABLE vss USING vec0(...)"` rejected before running | The batch runs; the declared table being virtual is caught after, as `DirSqlError::TableIsVirtual` | Keep `name` on a real row table and declare the virtual table alongside it in the same batch. |

#### Deprecations removed

- `DbError::DdlParse` — removed outright, with `db::is_virtual_table_ddl` and
  `db::is_without_rowid_ddl`, the two whitespace-normalizing string sniffs
  behind it.

#### Behavior changes without code changes

- **Every statement in `ddl` now runs.** `Connection::execute` prepared only the
  first and discarded the tail, so a config with `CREATE TABLE t (...); CREATE
  INDEX ...` silently created the table without the index, and one whose second
  statement SQLite could not parse still loaded. Both now behave as written: the
  index is created, and the unparseable batch is a load error.
- **A batch SQLite rejects leaves nothing behind**, and its error carries the
  config entry: `table 'messages': SQLite error: near "(": syntax error`.
  Previously the first statement of a partly-invalid `ddl` took effect.
- **A `[[table]]` whose `name` resolves to a virtual table is a load error**
  raised after the batch runs, not a string match before it. A batch is now free
  to create as many virtual tables as it likes under other names.
- **`WITHOUT ROWID` is detected from the catalog's `wr` flag** rather than from
  the DDL text. Same warning, same "will be rejected in a future release"
  wording; a `WITHOUT ROWID` *shadow* table belonging to some other virtual
  table no longer triggers it.
- **The persistent-cache sweep drops virtual tables first**, derived from
  `pragma_table_list`'s type instead of `sqlite_master`'s creation order, and
  leaves shadow tables to the virtual table that owns them.
- **Editing any part of `ddl` still invalidates a persistent cache** — the
  config hash already covered the whole string, and now that the whole string
  runs, that is the single invalidation lane for indexes, tokenizers and
  embedding model ids alike. Rows a batch inserts itself are not file-tracked:
  they survive file deletions and vanish on a rebuild.

#### Verification

```bash
# .dirsql.toml
#   [[table]]
#   name    = "records"
#   glob    = "data/*.json"
#   on-file = "cat {path}"
#   ddl     = '''
#   CREATE TABLE records (id TEXT, body TEXT);
#   CREATE INDEX records_id ON records(id);
#   CREATE VIRTUAL TABLE records_fts
#     USING fts5(body, content='records', content_rowid='rowid');
#   CREATE TRIGGER records_ai AFTER INSERT ON records BEGIN
#     INSERT INTO records_fts(rowid, body) VALUES (new.rowid, new.body);
#   END;
#   '''

dirsql query "SELECT name FROM pragma_index_list('records')" -c ./.dirsql.toml
# -> [{"name":"records_id"}]          (before: [], the CREATE INDEX was dropped)

dirsql query "SELECT body FROM records_fts WHERE records_fts MATCH 'hello'" \
  -c ./.dirsql.toml
# -> [{"body":"hello world"}]

# Truncate the batch's last statement:
dirsql query "SELECT id FROM records" -c ./.dirsql.toml
# -> error: table 'records': SQLite error: incomplete input
#    (before: exit 0 — the tail was silently ignored)

# Point `name` at a virtual table:
dirsql query "SELECT id FROM records" -c ./.dirsql.toml
# -> error: table 'records': its `ddl` created a virtual table called 'records'.
```
