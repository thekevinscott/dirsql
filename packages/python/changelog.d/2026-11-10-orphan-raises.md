**Changed** While a watch batch is held because it left a row whose foreign key matches nothing, every query raises that foreign-key violation: the same rule as a failing `on_file` hook, which makes every query raise until its file is fixed. The index keeps its last consistent state, and queries succeed again once a later change lands the batch: the missing parent appears or the orphaned child is removed. While a file is failing as well, a query raises the failing file's error first (the first by table, then path) and the foreign-key violation only once no file is failing. The error still reaches `watch()` consumers as before.
